## 2. Dependency inventory and dataflow

### 2.1 End-to-end retained pathway

```text
PreparedDataset / DatasetRecord
  ├─ RGB asset + original dimensions
  ├─ component occurrence IDs + original-pixel xyxy boxes
  ├─ pizza/component targets + known masks (supervision contract)
  └─ detector-category IDs (annotation metadata)
       │
       ├─ load_prepared_dataset / deterministic_subset
       └─ collate_image_records
             ├─ ImageNetLetterbox → normalized [B,3,224,224] + ImageGeometry
             └─ ImageBatch (ragged GT boxes, occurrence IDs, categories, targets/masks)
                  │
                  └─ SharedVisualFeatureExtractor.forward
                       ├─ GroundTruthROIProvider (default; original-image boxes)
                       ├─ one MobileNetV3-Large/FPN pass
                       ├─ component MultiScaleRoIAlign → mean [N,256] + coords [N,4]
                       │      → padded component_vectors [B,K,260], valid mask, occurrence IDs
                       └─ separate full-original-image MultiScaleRoIAlign
                              → global_spatial_features [B,256,7,7]
                                   │
                                   └─ ImagePointModel.forward(features, sample_ids)
                                        ├─ component_points [B,K,d]
                                        ├─ global_pizza_points [B,d]
                                        ├─ composed_pizza_points [B,d]
                                        └─ selected final_pizza_points [B,d]
                                              → ImagePointResult (points + identities only)
```

**[SOURCE-VERIFIED]** The real dependency chain is `dataset.image_data` / `dataset.schema` → `vision.batching` / `vision.preprocessing` → `vision.roi` / `vision.backbone` / `vision.features` → `models.image_points` and `contracts`. The point model accepts precomputed `VisionFeatureBatch` plus caller-provided sample IDs. There is no image-to-classifier call in this retained pathway.

### 2.2 Data and annotation contracts

- **[SOURCE-VERIFIED]** `dataset/schema.py::ComponentRecord` stores `component_id`, detector category ID/name, `bbox_xyxy_original`, ontology target/known-mask vectors, and annotation path. `DatasetRecord` stores split, generator type, image path/dimensions, pizza targets/masks/source labels, component records, audit and source-annotation metadata.
- **[SOURCE-VERIFIED]** `dataset/image_data.py::load_prepared_dataset` validates the prepared dataset, establishes trainable class IDs in the canonical manifest order, and exposes separate pizza/component supervision ID sets. `targets_in_trainable_order` projects vectors to that order. `deterministic_subset` selects only within the requested original split; it does not repartition records.
- **[SOURCE-VERIFIED]** `dataset/validation.py` checks stable component occurrence identity, duplicate IDs, category mapping, original-image box validity, annotation agreement, and target/mask contracts. Dataset records—not an image model—own semantic labels and unknown masks.
- **[SOURCE-VERIFIED]** `vision/batching.py::collate_image_records` resolves image paths under the dataset root, verifies RGB mode/dimensions, converts records to tensors, and creates `ImageBatch`. The batch includes targets/masks and category IDs for supervision/provenance, but the visual point heads do not accept that batch.
- **[SOURCE-VERIFIED]** `contracts.ImageBatch.validate` checks finite images/targets, binary known targets, ragged field lengths, and original-pixel component boxes. Occurrence IDs and validity are separately transported; padded IDs become `None` downstream.

### 2.3 Preprocessing, FPN and ROI extraction

- **[SOURCE-VERIFIED]** `vision/preprocessing.py::ImageNetLetterbox` accepts a PIL image, converts it to RGB, scales aspect-preservingly to a square resolution (default 224), centers it on a black canvas, converts to float32, and applies ImageNet mean/std normalization. No stochastic augmentation is present in this transform. `ImageGeometry` records original/processed/resized sizes, actual x/y scales, and left/top padding.
- **[SOURCE-VERIFIED]** `transform_boxes_xyxy` and `inverse_boxes_xyxy` map pixel-edge boxes using that recorded geometry. `normalized_roi_coordinates` returns `(cx/W, cy/H, w/W, h/H)` in original-image coordinates.
- **[SOURCE-VERIFIED]** `vision/backbone.py::MobileNetV3LargeFPN` selects MobileNetV3-Large feature indices 3/6/12/16, documented as channels 24/40/112/960 and strides 4/8/16/32. At the default 224-square input the tested FPN spatial sizes are 56×56, 28×28, 14×14 and 7×7. Torchvision `FeaturePyramidNetwork` produces 256-channel maps `0`–`3` and an extra max-pooled `pool` level. The current ROIAlign modules use maps `0`–`3`, not `pool`.
- The backbone uses Torchvision ImageNet MobileNet weights when `pretrained=True`; the FPN is instantiated in source without a detector checkpoint. **[SOURCE-VERIFIED]** This is a visual feature extractor, not Faster R-CNN or a detector-pretrained model.
- **[SOURCE-VERIFIED]** `vision/features.py::SharedVisualFeatureExtractor.forward` validates the batch/provider, computes one shared FPN pass, maps supplied original-pixel component boxes through `ImageGeometry`, and applies `MultiScaleRoIAlign(output_size=7, sampling_ratio=2)` for components. It averages each `[256,7,7]` ROI spatially, concatenates the four normalized box coordinates, and returns `[B,K,260]` with a boolean validity mask and occurrence IDs.
- Global features use a second ROIAlign invocation over the *transformed original-image extent*, not the padded canvas extent, yielding `[B,256,7,7]`. The global feature path is separate from component-ROI selection after the shared FPN maps are computed. Empty-component images still have global features.
- **[SOURCE-VERIFIED]** `GroundTruthROIProvider` is the default and current config requires `roi_source="ground_truth"`. `ExplicitROIProvider` demonstrates provider substitution; it does not implement detector predictions, matching, or training. Category/confidence fields may exist in `ROIIdentity`, but `SharedVisualFeatureExtractor` appends only occurrence identity, box-derived features, and pooled visual values.

### 2.4 Semantic point heads, composition and identities

| Module/function | Verified operation and output | Parameter/state boundary |
|---|---|---|
| `ComponentPointProjection` | `[B,K,260] → Linear(260,256) → LayerNorm/ReLU → Linear(256,128)/ReLU → Dropout(0.1) → Linear(128,d) → tanh`; result `[B,K,d]`. | Linear and LayerNorm parameters are trainable by default. Dropout is mode/RNG-dependent; no running-statistic buffer is introduced by this head. |
| `GlobalPointProjection` | `[B,256,7,7] → Conv2d(256,32,1×1) → flatten(1568) → Linear(1568,256)/ReLU → Linear(256,d)/tanh`; result `[B,d]`. | Conv/linear parameters trainable by default; no normalization running state. |
| `DeepSetsComposition` | Shared `phi: d→128→128` with ReLU, multiply by occurrence-valid mask, sum over `K`, then `rho:128→128→d` with final tanh; result `[B,d]`. Empty sets pass `rho(0)`. | `phi` and `rho` linear parameters trainable by default. Sum preserves permutation invariance and makes multiplicity visible to the aggregate; it does **not** guarantee distinct final outputs for every duplicate pattern/weight setting. |
| `HybridPointFusion` | Concatenate global and composed points `[B,2d]`, `Linear(2d,128)/ReLU → Linear(128,d)/tanh`; result `[B,d]`. | Linear parameters trainable by default. |
| `ImagePointModel` | Instantiates all heads/composition/fusion under a seeded CPU RNG fork. It computes all intermediate outputs; `pizza_mode` selects global, compositional, or hybrid `final_pizza_points`. Returns point tensors, mode, sample IDs, component IDs/valid mask, and optional diagnostics. | `common_state_dict()` exposes point/composition/fusion state. No classifier, class order, logits, margins, membership, loss, or prediction parameter/state exists in this model. |

**[SOURCE-VERIFIED]** All current image point-producing heads end in `tanh`, so emitted points lie in the bounded domain. `d` is configurable and must be a positive integer. Component identity is transported per occurrence; repeated occurrences occupy separate slots. One final pizza point is returned per batch sample. There is no class/category-specific output.

**Identity boundary:** `VisionFeatureBatch` carries component IDs but not sample IDs; `ImagePointModel.forward` receives sample IDs separately. The model checks batch length/mask shapes but does not establish that caller-provided sample IDs correspond to the supplied feature rows or validate every component-ID tuple against the mask. **[UNRESOLVED]** This is a caller-alignment assumption in the retained low-level API, not evidence of observed misalignment.

## 3. Trainability, mutable state, gradients and caching

- **[SOURCE-VERIFIED]** `VisionConfig` defines `frozen`, `trainable_fpn`, and `trainable_fpn_last_blocks`; its default is frozen. `build_visual_feature_extractor` constructs the backbone and applies policy. `MobileNetV3LargeFPN.set_trainable` first freezes all MobileNet parameters, optionally re-enables selected blocks, and toggles FPN parameters. Its overridden `train()` places frozen MobileNet blocks and a frozen FPN in eval mode.
- **Mutable-state implication:** frozen MobileNet blocks are explicitly eval-mode, so their BatchNorm running state should not update under normal PyTorch module semantics. Selected trainable MobileNet blocks remain in the caller's train/eval mode and can carry mutable normalization buffers. **[SOURCE-VERIFIED]** The retained vision test checks parameter `requires_grad` and FPN gradient presence, but does not snapshot running buffers before/after a train-mode forward. This dynamic buffer behavior was not probed in CP1.
- **[SOURCE-VERIFIED]** The direct `MobileNetV3LargeFPN` constructor enables FPN training by default; `build_visual_feature_extractor(config)` resets it according to `VisionConfig`. Thus policy conclusions apply to the configured factory path, not to every caller that constructs the backbone directly.
- **[SOURCE-VERIFIED]** `ImagePointModel` parameters are trainable by normal `nn.Module` defaults. The visual extractor is not automatically frozen, wrapped in `no_grad`, or switched to eval by `SharedVisualFeatureExtractor.forward`; caller mode/configuration determines gradient and mutable-state behavior. The frozen cache producer explicitly sets eval and uses `torch.no_grad()`.
- **[SOURCE-VERIFIED]** `experiments/visual_features.py::_set_seed` mutates Python, NumPy, Torch CPU/CUDA RNGs and cuDNN deterministic/benchmark flags when constructing the visual extractor; it does not restore prior process-wide RNG/flags. `ImagePointModel.__init__` uses `torch.random.fork_rng(devices=[])` for its manual seed. **[UNRESOLVED]** Whether the visual-factory global side effect matters to any future caller has not been measured here.
- **[SOURCE-VERIFIED]** `prepare_frozen_feature_cache` permits only frozen visual features, builds assets from train/validation subsets, rejects test rows, uses GT ROIs, and hashes dataset/subset/sample/split/class-manifest identity, visual state, backbone/FPN/preprocessing/version/device metadata. Cache assets contain visual component/global features and occurrence IDs, not targets, categories, checkpoints, optimizer state, or test rows. Each feature asset is checksummed. The read API verifies producer identity, checksums and occurrence IDs.
- Cache generation sets `visual.eval()`, stores/restores Torch CPU/CUDA RNG state, and restores the prior top-level `visual.training` mode in `finally`; model parameters are not optimized. Cache identity does not include point-head/composition state because it caches visual features only. **[SOURCE-VERIFIED]** `FrozenFeatureCache.get` constructs CPU tensors; there is no active classifier trainer to consume the cache in the current baseline.
- **Gradient evidence boundary:** image point layers are ordinary differentiable PyTorch modules and the visual path is configured for gradients when trainable. This structural fact is not equivalent to current learning. The current `ImagePointModel` tests do not backpropagate through its heads. Historical Phase 3 reports document gradient-path tests/runs at pre-teardown revisions; those classifier-dependent tests were retired during T3.

### Other unresolved investigation questions (no architecture choice)

1. **Mode-specific gradient/accounting:** `ImagePointModel.forward` computes every head and composition for all modes, while `final_pizza_points` selects only one branch. Which returned intermediates receive supervision is a training-contract question; current classifier training is disabled. The issue's historical architecture report says only the final selected pizza point receives pizza supervision, but that is historical implementation behavior, not an active objective.
2. **Identity alignment:** sample IDs are separate caller input; feature rows do not carry sample IDs. Whether to validate identity alignment at a future integration boundary is unapproved engineering scope.
3. **Domain/activation identity:** ADR-0002 identifies activation/domain as semantic checkpoint identity for a future unbounded model. Current config has no such field because only bounded points are implemented. No checkpoint path currently executes.
4. **Train config reconciliation:** retained metadata defaults differ from A1/F12 initial training policy (above). They must not be interpreted as current settings or silently reused if training is separately authorized.
5. **Visual feature initialization/cache scope:** ImageNet MobileNet weights and the randomly initialized FPN are historical engineering choices; neither constitutes detector pretraining. Cross-device cache parity and transferability are unmeasured in CP1.
6. **Static source navigation:** `training/image_trainer.py`'s module docstring points to `town_model.vision.factory`; no such module exists in the audited tree. The actual builder is `experiments.visual_features.build_visual_feature_extractor`. This is a verified documentation pointer mismatch, not evidence of a runtime defect.

## 8. CP1 conclusion and limits

**[SOURCE-VERIFIED]** The retained image pathway is a classifier-independent image-to-point foundation: prepared records and GT component ROIs feed a shared MobileNetV3-Large/FPN feature extractor, then bounded component/global point projections, masked sum-based DeepSets composition and optional hybrid fusion. It preserves sample/occurrence identity and known-mask dataset contracts. The feature/cache surfaces remain independently callable.

**[SOURCE-VERIFIED]** The current operational boundary is different from historical Phase 3: classifier construction, scoring, training, evaluation, run/resume, classifier-dependent snapshot generation and geometry dashboard execution are disconnected and fail unavailable. The retained API does not emit classifier predictions. Historical Phase 3 acceptance does not reverse the T0–T5 teardown.

**[HISTORICALLY REPORTED]** Small pre-detector experiments demonstrate that component and pizza metrics varied across configurations: some component and corrected baseline/town runs improved; early pizza metrics were zero in selected runs; corrected box hard-membership F1 remained poor while its hinge loss decreased. Reports preserve the data/scope and do not establish a causal account or thesis conclusion.

This report does **not** recommend retaining, refactoring, or removing any visual module; select a backbone, pooling rule, coordinate feature, composition semantics, domain implementation, detector policy, loss, training setup or experiment; authorize CP2/CP3; or declare CNN-00 accepted. The thesis author should review this CP1 report and select/authorize any empirical probes before they begin.
