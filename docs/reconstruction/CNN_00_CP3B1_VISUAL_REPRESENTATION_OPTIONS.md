## 2. Pinned baseline and shared invariants

### 2.1 Source-observed pathway

At `404d761…`, the retained path is:

```text
RGB → ImageNetLetterbox + ImageGeometry
    → MobileNetV3-Large taps (indices 3/6/12/16) → 256-channel FPN
        ├─ component original-pixel ROIs → multi-scale ROIAlign 7×7
        │    → spatial mean (256) + normalized box coordinates (4)
        │    → [B,K,260] + component-valid mask + occurrence IDs
        └─ separate full-original-image ROI → [B,256,7,7]
             → existing global point projection

[ B,K,260 ] → existing component-point projection ─┐
[ B,256,7,7 ] → existing global-point projection ─┼→ existing point/composition modes
                                                    └→ ImagePointResult (points/IDs only)
```

- **[SOURCE] Backbone/FPN:** [`vision/backbone.py`](https://github.com/midhunpradeep/town_model/blob/404d76112a9d53282b3f55698b4decb705a5601c/src/town_model/vision/backbone.py#L16-L95) taps MobileNetV3-Large feature indices 3/6/12/16, documented as 24/40/112/960 channels at strides 4/8/16/32. TorchVision FPN maps have 256 channels; its extra stride-64 `pool` output is emitted but the current ROIAlign modules use maps `0`–`3` only. At the configured 224-pixel input, inspected source/tests describe 56×56, 28×28, 14×14 and 7×7 maps.
- **[SOURCE] Initialization:** the source uses TorchVision `MobileNet_V3_Large_Weights.DEFAULT` when ImageNet pretraining is enabled, then constructs a new FPN module with the library’s default layer initialization and no detector checkpoint. The visual-extractor factory seeds the process before module construction; CP1 notes that this factory changes process-wide RNG/cuDNN settings. TorchVision 0.20 documents `DEFAULT` as `IMAGENET1K_V2` classification weights. The FPN initialization is therefore distinct from the MobileNet weights and is not separately configurable as a pretrained detector FPN. The project’s `ImageNetLetterbox` uses square letterboxing plus ImageNet normalization; the official MobileNet weights’ documented transform uses resize plus center crop, so the preprocessing is not identical. Neither fact proves a transfer problem or useful Pizzaïolo features.
- **[SOURCE] Component boundary:** [`vision/features.py`](https://github.com/midhunpradeep/town_model/blob/404d76112a9d53282b3f55698b4decb705a5601c/src/town_model/vision/features.py#L18-L110), [`vision/preprocessing.py`](https://github.com/midhunpradeep/town_model/blob/404d76112a9d53282b3f55698b4decb705a5601c/src/town_model/vision/preprocessing.py#L17-L110), and [`vision/roi.py`](https://github.com/midhunpradeep/town_model/blob/404d76112a9d53282b3f55698b4decb705a5601c/src/town_model/vision/roi.py#L13-L55) carry original-pixel `xyxy` boxes through recorded resize/pad geometry. Component features are ROIAlign `[256,7,7]`, mean over spatial axes, plus `(cx/W, cy/H, w/W, h/H)` from original-image dimensions. The output is padded `[B,K,260]`, with a separate boolean validity mask and occurrence IDs; `K=0` is supported.
- **[SOURCE] Global boundary:** `SharedVisualFeatureExtractor` issues a distinct ROIAlign call on the transformed full original-image extent, not the letterbox canvas extent, and returns `[B,256,7,7]` even when the component set is empty. Both ROI calls use the same FPN maps from one backbone pass. `MultiScaleRoIAlign` assigns ROIs to pyramid scales using its documented scale heuristic; this should not be described as concatenating all pyramid levels for each ROI.
- **[SOURCE] Feature consumer:** [`models/image_points.py`](https://github.com/midhunpradeep/town_model/blob/404d76112a9d53282b3f55698b4decb705a5601c/src/town_model/models/image_points.py#L15-L158) expects the retained feature shapes and produces points, not classes or geometry membership. The global head currently applies a 1×1 convolution to 32 channels, flattens the 7×7 grid (1568 values), and applies a dense projection. No B1 option changes its point-domain or hybrid-fusion semantics.
- **[SOURCE] Leakage/identity boundary:** [`contracts.py`](https://github.com/midhunpradeep/town_model/blob/404d76112a9d53282b3f55698b4decb705a5601c/src/town_model/contracts.py#L24-L158) transports image pixels, targets/masks, original boxes, sample IDs and detector-category metadata. The component vector receives visual ROI values and permitted pixel-derived coordinates, not category IDs, confidence, targets or known masks. Provider metadata may carry IDs/category/confidence, but the current visual vector does not concatenate those metadata fields. Occurrence identity, component-valid/padding masks, and A1 known-label masks are distinct. Any replacement must keep them distinct and retain one output point for every observed occurrence.
- **[SOURCE] Current stage and inspection boundary:** [`VisionConfig`](https://github.com/midhunpradeep/town_model/blob/404d76112a9d53282b3f55698b4decb705a5601c/src/town_model/experiments/image_config.py#L91-L122) fixes the retained backbone name, 256 FPN channels, 7×7 ROI size and GT-only source; its factory default is frozen. ## 3. Boundary 1 — visual backbone, FPN, initialization, and frozen state

### 3.1 Current design and evidence

**[SOURCE]** `MobileNetV3LargeFPN` taps four MobileNetV3-Large stages and applies a top-down/lateral FPN producing 256-channel levels plus an extra pooled map. The retained ROI paths consume only levels `0`–`3`. The configured factory takes ImageNet initialization for MobileNet when enabled; it does not initialize the FPN from a detector checkpoint. The `pretrained_imagenet` switch and `visual_policy` are extractor configuration choices, not scientific-stage selection; no detector stage is selected.

**[SOURCE + CP2/P7]** In the configured `frozen` policy, MobileNet and FPN parameters are non-trainable and frozen modules are put in eval mode. CP2 P7 observed, for one synthetic 64×64 forward, unchanged values across 5,624,112 parameters and unchanged frozen buffers. Its trainable-last-block fixture observed that block 16’s BatchNorm counter/running buffers changed in train mode; this is expected state behavior for that policy. These are bounded extractor observations, not evidence of detector Stage 2 or a Stage-3 lineage.

**[MATH/CONTRACT]** Freezing parameter gradients alone is not equivalent to freezing mutable module state: BatchNorm-like buffers can change in train mode. F9.1 explicitly includes mutable state in Stage-2 freezing. A replacement normalization scheme also needs an explicit train/eval/state policy. ImageNet classification pretraining (classification labels, ImageNet weights) is different from a selected Stage-1 detector checkpoint trained on the target detection task. ImageNet MobileNet weights plus a newly initialized FPN are not detector pretraining.

### 3.2 Option A — retain the current MobileNetV3-Large/FPN arrangement

- **Contracts:** Keep taps 3/6/12/16, current strides/channel inputs, 256-channel FPN maps, extra `pool` map, current ROI scale assignment, current initialization behavior, and the component/global output contracts. Preserve `ImageNetLetterbox`, GT original-pixel box transforms and ROI provider boundaries.
- **Expressiveness / bias:** Retains a mobile-oriented CNN’s hierarchical convolutional features and a standard pyramid that supplies representations at several spatial scales. Multi-scale availability does not prove the correct feature level is selected for each Pizzaïolo ROI, nor that any level encodes useful ontology distinctions. The extra `pool` level is available in the extractor but is not used by the present ROI paths.
- **Optimization / state:** Existing choices offer frozen, FPN-trainable, and FPN-plus-selected-MobileNet-block policies. With `frozen`, the existing extractor can provide fixed features while point-side modules are trained in a future authorized system. A stage-2 detector lineage is still absent. For `trainable_fpn_last_blocks`, selected normalization buffers may be mutable; this policy cannot be silently equated with F9 Stage-2 freeze.
- **Stage compatibility:** As-is is a pre-detector feature path. To satisfy F9, a later Stage 1 would have to train/select a detector and checkpoint; Stage 2 must initialize from that detector checkpoint, use GT ROIs, and freeze all visual parameters and mutable state; Stage 3 must descend from Stage 2 and use real predicted ROIs with specified detached coordinate/discrete-selection paths. An ImageNet weight flag cannot stand in for those transitions.
- **Estimated cost:** At 224 input the four used maps contain 4,165 spatial cells; the extra stride-64 map is about 4×4. The five 256-channel output maps therefore contain about 1.07 million float values (about 4.08 MiB/image in fp32) before accounting for backbone activations, temporary workspaces, ROI tensors, gradients, or allocator overhead. A useful symbolic estimate is `backbone_cost + Σ_l(H_l W_l C_l·256 + 9 H_l W_l·256²)` MACs for the FPN lateral and 3×3 output convolutions, plus ROIAlign. This is an operation estimate, not measured speed or a whole-model FLOP count. At fixed width/resolution, batch size and trainable activation retention scale memory materially.
- **Cache/checkpoint identity:** Existing cache identity includes a visual-state hash, initialization label, backbone architecture, FPN input indices/channels/output width, preprocessing, ROI source, extraction-contract version, library versions and producer device. Retaining current tensors allows existing frozen-cache contracts to remain meaningful. Any future detector checkpoint still needs separate architecture, exact checkpoint/weight identity, stage lineage and trainability/state metadata.
- **Inspection / BOX-TOWN:** A future authorized inspection could show FPN levels/strides, initialization provenance, ROI scale assignment and checkpoint lineage while preserving current read-only constraints. Points still flow to existing `[N,d]` interfaces; no class/category feature or geometry operation enters the CNN. Existing dashboard does not currently expose live feature maps or permit training.
- **Evidence and risk:** CP1 supports only source topology; CP2 P7 supports one-forward state behavior with random weights; neither establishes target-domain transfer, detection quality, feature sufficiency, optimizer success or superiority. The risk is treating a familiar/high-level design or ImageNet weights as evidence that detector-stage requirements or target semantics are met.

### 3.3 Option B — refactor internal seams without changing the feature function

- **Scope:** Separate encoder, FPN, feature-level metadata, initialization provenance, trainability/state policy and ROI feature consumer into clearer internal seams while preserving the same maps, weights, forward computations, feature names, output tensors and provider behavior. The intent is navigability and explicit provenance, not a new encoder or neck.
- **Contract test for the option (proposed, not run):** Require same input preprocessing, map names/shapes/strides, exact configured weight source, same initialization state and train/eval modes, same ROI level assignment, same output values within an author-approved numerical tolerance, same gradients/state behavior, coordinates, identities, masks and cache meaning. A code move that changes outputs or mutable-state behavior is not this semantics-preserving refactor.
- **Expressiveness / optimization:** By definition, a strictly behavior-preserving refactor changes neither representable function nor inductive bias. It should leave the active trainable parameter set and gradients unchanged. Any “cleanup” that changes normalization, stage selection, initialization or FPN topology crosses into architecture replacement/author choice.
- **Stage/cost:** No asymptotic compute/memory change is expected if the executed graph is identical; no gain is claimed without measurement. The refactor does not create detector pretraining or solve Stage-1/2/3 lineage.
- **Identity/inspection:** Internal module names may affect state-dict keys, feature-cache hashes and checkpoint restore. A refactor must decide whether state identity is deliberately preserved/migrated or version-bumped; matching tensor shapes are insufficient. A typed architecture descriptor could make provenance easier to inspect, but should not silently reopen model/checkpoint or dashboard routes.
- **BOX/TOWN:** If point heads and domains remain unchanged, the external flat point boundary remains. Reordering or changing feature rows/weights can still change the learned points and therefore requires experiment/checkpoint provenance even when `[B,K,260]` is unchanged.
- **Assessment:** A narrow refactor is conditionally justified if a specific maintenance/provenance problem is demonstrated and parity can be established. CP1/CP3-A identify interfaces but no report demonstrates that a refactor is necessary; there is no evidence-backed reason here to change the current computation.

### 3.4 Option C — replace the visual encoder/neck or use a different initialization source

Technically credible *candidates for later author discussion*, not a ranking or selection, include: a residual CNN feeding FPN; a ConvNeXt hierarchical ConvNet feeding FPN; a hierarchical shifted-window Transformer (for example Swin) exposing multi-stage maps with an adapted pyramid/readout; or, after a separately selected Stage-1 detector exists, loading that detector’s backbone/FPN checkpoint for Stage 2. These differ in stage structure, channel widths, receptive-field/context behavior, normalization, parameter count, compute, weights and ecosystem support. A change to detector pretraining is not the same candidate as swapping ImageNet classification backbones.

- **Contracts and changes:** A replacement can be adapted to emit four 256-channel maps and keep downstream tensor shapes, but equal channels do not make feature meanings or weights compatible. Different levels/strides, map names, ROI assignment, input normalization, `pool` behavior, or ROI extraction alter the visual contract. Replacing the global/component readouts at the same time would confound causes and is outside a single-boundary comparison. Any architecture change is an author-owned choice; changing an approved tensor/cache contract is an explicit additional approval gate.
- **Expressiveness / inductive bias:** Residual, modern convolutional and hierarchical attention families supply different local/contextual mixing and stage hierarchies. They may differ in feature diversity and spatial support. These are architecture properties/hypotheses, not a proof that any candidate represents relevant Pizzaïolo predicates better. Increasing feature complexity also raises data/optimization demands and can overfit.
- **Optimization / frozen state:** Different parameters, initialization distributions and normalization modules change gradient scales, mutable buffers, optimizer groups and memory-for-backprop. Stage-2 frozen state must include the selected detector’s complete visual parameters and mutable state; Stage-3 must resume from its Stage-2 descendant and expose only the approved shared-feature gradient path. A new encoder/readout needs explicit stage-aware `requires_grad`, module mode, normalization-buffer and checkpoint lineage policies.
- **Estimated cost:** No relative latency claim is justified here. For an input of fixed size, convolutional MACs scale with each stage’s `H·W·C_in·C_out·kernel_area`; windowed/global attention alternatives have their own token/window and projection costs. A more expressive or wider encoder may increase parameter count, activation memory and training cost; a more efficient one may not be faster on the project’s actual CPU/GPU/runtime. Require measured target-hardware evidence if cost is a decision criterion.
- **Cache/checkpoint/experiment identity:** New encoder/neck, initialization checkpoint digest, exact MobileNet/TorchVision weight enum, normalization/preprocessing, feature-stage indices/strides, FPN initialization, trainable blocks, normalization state and ROI assignment must be versioned into producer identity. Existing `frozen-vision-feature-cache-v1` and old state hashes must not be reused as if features were equivalent. Future experiment comparisons must identify detector checkpoint and stage ancestor, not only say “pretrained.”
- **Dashboard / BOX-TOWN:** A later approved dashboard comparison would need model and weight provenance, stage/ROI source, feature-level and shape information, and a trace from original image/ROI to visual tensor to point. Keep stored diagnostics explicitly labeled and read-only unless a separate accepted implementation reauthorizes generation. The BOX/TOWN interface remains point-only; the CNN replacement does not own class rows, membership, clearance, or the bounded/unbounded policy.
- **Risks / approval:** This is a material architecture and scientific-comparison choice, even if output shapes match. The author must approve the actual candidate, initialization policy, stage placement and comparison scope. CP3-B1 selects none.

### 3.5 Conditional assessment and evidence that could distinguish options

- **If** the immediate objective is to preserve the accepted image-to-point foundation and current cache/interface identity, **then** retaining the present extractor is the least disruptive reference condition; that is a compatibility argument, not evidence of optimality.
- **If** a source-level maintainability/provenance problem is demonstrated and the same computation/state can be preserved, **then** a narrow refactor could improve clarity without adding a scientific alternative. No such need is established by this report.
- **Only if** an author-approved, controlled, stage-compatible comparison demonstrates a relevant feature, optimization, runtime, or memory limitation should replacement be considered. It should hold approved data/splits, ROI source, heads/readout, training policy and selection criteria constant where possible; select/compare by the author-approved validation protocol; keep final held-out claims separate under an approved protocol. F11 requires separating representability, numerical feasibility, optimization and generalization. No test split or thresholds are supplied here.

**Future falsifiers (not executed):**

1. A static contract audit can falsify a claimed parity refactor by showing changed taps/strides/channels, ROI assignment, weights, outputs, parameter flags, module modes, mutable buffers, IDs/masks or cache identity.
2. A stage-state verification can falsify “frozen” by any parameter or mutable-buffer change during an authorized Stage-2 forward; it must use the selected detector checkpoint and full state, not only the CP2 synthetic extractor fixture.
3. An author-approved feature/learning comparison can falsify a replacement’s claimed benefit if it fails the predeclared target validation criterion or violates the declared compute, state, or provenance constraint. The protocol and criterion must be author-supplied; this report invents neither.

## 4. Boundary 2 — component ROI representation and 260-dimensional vector

### 4.1 Current design and information boundary

**[SOURCE]** Each original-pixel component box is transformed by `ImageGeometry`, pooled from selected FPN scales into `[256,7,7]`, then reduced by a spatial mean per channel. Four box-derived values `(cx/W, cy/H, w/W, h/H)` are appended. The result is `[B,K,260]`. Component occurrence IDs and a boolean valid mask are separately carried; category IDs, confidence and label/known-mask vectors are not part of the feature vector. Padding slots are not real occurrences; an empty set produces `[B,0,260]` and `[B,0]` validity.

**[MATH] What mean pooling necessarily loses:** Let `X ∈ R^(256×7×7)` be an arbitrary pooled ROI tensor. The channelwise mean is a linear map from 12,544 scalar inputs to 256 values. Its rank is at most 256, with a null space of dimension at least 12,288. For any nonzero per-channel spatial perturbation whose 49 entries sum to zero, `X` and `X+δ` have the same means. Holding the four box coordinates fixed, appending those coordinates cannot recover `δ`. Thus this readout is non-injective and discards within-ROI arrangement information for arbitrary tensors.

This is **not** evidence that a target-relevant semantic difference is actually lost on this dataset. FPN channels can encode context, position-sensitive patterns or larger receptive-field information before pooling; the box coordinates add region location/scale; the separate global pathway provides image context. No accepted CP1/CP2/CP3-A result measures whether those cues recover the distinctions needed for component predicates or relations.

**[CP2/P4]** The accepted synthetic fixture showed different component features for its two chosen ROI sets and exact global-feature equality across component-provider variants. This establishes controlled ROI sensitivity/independence only; it says nothing about semantic sufficiency.

### 4.2 Option A — retain spatial mean plus four coordinates

- **Contracts:** Preserve exactly the 260-vector: mean of the 7×7×256 visual ROI plus the four normalized coordinates. Keep original-pixel box transforms, component occurrence identity, valid mask, empty-set support, and no category/target leakage.
- **Expressiveness / bias:** Retains per-channel average activation and explicit region position/scale, while imposing invariance to within-ROI rearrangements that preserve every channel mean. This is a strong, parameter-free pooling bias. It can reduce spatial detail and downstream head size; it does not prove semantic loss or model insufficiency.
- **Optimization / stage:** Mean is fixed and has no trainable parameters; for a given channel, the direct derivative to every ROI cell is the same `1/49` factor before upstream chain-rule effects. This may make optimization simpler than a learned spatial encoder, but no learning advantage is established. In future stages, the backbone/FPN’s trainability still controls feature-map gradients; GT/predicted box coordinates and their detachment follow F9, not the pooling choice.
- **Estimated cost:** Per component ROI, the pre-mean tensor has 12,544 fp32 values (49 KiB); a simple mean uses O(256×49) reductions and returns 260 fp32 values (about 1.02 KiB). ROIAlign work/activation storage grows approximately linearly with the number of component ROIs `K`; training-time autograd can retain more than the returned vectors.
- **Identity / inspection:** Current cache records the 260 values and normalized coordinates, along with architecture/weights/preprocessing/ROI source and extraction-contract identity. Keep its feature meaning/version explicit. Future authorized inspection should be able to distinguish pooled channel means and coordinates from raw spatial ROI grids; current dashboard/snapshot behavior remains metadata-only/read-only.
- **BOX/TOWN:** Output heads continue to consume `[B,K,260]` and emit one `[d]` point per valid occurrence. Preserve exact occurrence ordering and masks so later flat `[N,d]` classifier calls can reconstruct point-to-occurrence association. No geometry or label inputs are added.
- **Evidence / risk / gate:** Source confirms operation and CP2 P4 shows fixture sensitivity, but no semantic or optimization evaluation exists. Retaining is compatible with current consumers, not a claim that averaging is scientifically best. The `[B,K,260]` interface remains protected absent author approval.

### 4.3 Option B — contract-preserving refactor of the ROI adapter/readout seam

- **Scope:** Isolate (a) original-pixel box transformation, (b) FPN-scale ROI sampling, (c) fixed spatial-mean readout, (d) coordinate-feature construction and (e) ragged padding/identity assembly into explicit components while retaining the same calculation and vector values. A refactor can make stage-specific box provenance and readout identity more inspectable.
- **What must not be called a refactor:** A learned convolution, attention pooling, spatial pyramid, changed coordinate formula, ROI size/scale heuristic, feature normalization, or output meaning is a changed representation, even if it still emits 260 floats. It belongs under replacement/architecture choice and needs author approval.
- **Expressiveness / optimization / gradients:** Under exact behavioral preservation, no information capacity, inductive bias or gradients change. The output remains mathematically non-injective in the same way. Any observed gradient or feature change means the refactor is not semantically equivalent and must be assessed as a replacement.
- **Stage/cost:** A value-preserving organization change has no expected asymptotic cost change; no speed benefit is claimed. A future API must preserve the F9 distinction between feature-map gradients and detached predicted coordinates, and keep any new learned parameters out unless separately authorized.
- **Identity / dashboard / BOX-TOWN:** Preserve the `260`-input point-head interface and tell the cache/checkpoint whether producer semantics are unchanged. If module renaming changes state keys or cache producer identity, migration/versioning must be explicit. Diagnostic presentation should retain original-pixel boxes, normalized coordinates, ROI source, occurrence IDs and validity separately. BOX/TOWN gets the same point rows and no new semantics.
- **Conditional assessment:** Justified only if a concrete code-organization or traceability problem exists. No source/evidence finding in CP1 or this CP3-B1 review requires such a refactor.

### 4.4 Option C — replace or augment the spatial readout

Candidate families for author discussion—not selected—include:

1. **Flatten and project** all `7×7×256` values (12,544 visual inputs) with the four coordinates. This preserves grid cells until the learned projection, but gives a larger, position-sensitive dense input and can overfit.
2. **Spatial-pyramid pooling** with multiple fixed spatial bins, retaining coarse layout at several resolutions. The exact bin schedule and any projection back to 256 are open choices; changing the vector width changes the retained 260-D contract. If projected back to 256, shape compatibility alone does not preserve the old mean semantics.
3. **Learned convolutional or attention-weighted pooling** over the ROI grid. These can weight locations non-uniformly and keep a fixed output width if designed to do so, but add parameters, initialization, optimizer/state and stage questions. Attention or a learned projection is not guaranteed to be injective or to preserve useful semantics.
4. **Other fixed spatial summaries** (for example, moments or multiple pooled statistics). They alter the representation and output width unless an explicit projection is added; they still may be non-injective.

- **Contracts / approvals:** Any change to the output dimension, exact 260 values or point-projection input requires explicit author approval as specified in the B1 authorization. Even a shape-preserving learned readout changes the architecture, checkpoint meaning and trainable-state boundary and therefore also requires an author decision. Preserve the same ROI source, occurrence identity, padding mask, original-pixel coordinates and visual-primary/no-category-leakage constraints unless separately approved.
- **Expressiveness / inductive bias:** Flattening can expose absolute bin locations to a learned dense layer; pyramid bins expose coarser layout; learned attention can select salient locations; fixed statistics add summaries. None is necessarily more useful, universally injective, or better on the thesis task. For a target dataset, semantic relevance remains empirical.
- **Optimization / stage compatibility:** Learned readout parameters add gradient paths and can trade sample efficiency for capacity. Their owner is unresolved: if part of the visual extractor/detector representation, F9 Stage 2’s frozen visual state appears applicable; if treated as point projection, a different stage policy may result. The author must define this boundary before stage implementation. Stage 3 must preserve feature-map gradient access while preventing ontology gradients through detached selected box coordinates and discrete detection decisions. F12.11/12.12 govern later stage optimizer transitions/defaults but do not resolve this module’s ownership.
- **Estimated cost:** Flattening does not itself add learned parameters but feeding 12,548 values to a same-width 256-unit first linear layer requires about 3.21M weights/MACs per occurrence, versus 66,560 weights in the current `260→256` first layer (about 48× for that layer, assuming the same hidden width; not a measured end-to-end cost). A 1×1/3×3 readout, pyramid or attention cost depends on its channels/bins/heads. All choices retain ROIAlign output memory unless pooling is moved into the ROI op; autograd memory remains stage-dependent.
- **Identity / inspection:** New readout name/configuration, learned state, initialization seed, ROI grid/channel convention and output semantics must enter cache/checkpoint/experiment identity. Existing frozen cache stores already-pooled 260-D values, not raw component `[256,7,7]` maps; it cannot support a new spatial readout without recomputing features or a separately versioned raw-map cache. Historical snapshots cannot be reinterpreted under T5. A future authorized microscope should expose each selected spatial summary alongside source ROI and axes, not merely report “260 features.”
- **BOX/TOWN:** Keep the downstream point space and `d` contract unchanged if the question is only ROI readout; a different representation can still change point distributions and invalidate old model/experiment comparisons. No class-conditioned or detector-category-conditioned pooling is compatible with the no-leakage requirement absent a new author-approved scientific decision.
- **Evidence / risks / gate:** The mathematical non-injectivity proof establishes an information bottleneck in this operation only. It does not establish semantic loss. A replacement requires an author-approved study that can distinguish spatial sensitivity from actual task utility, and must report capacity/parameter differences and initialization/optimization evidence separately. No 260-D change is authorized here.

### 4.5 Conditional assessment and discriminating evidence

- **If** there is no demonstrated task-relevant failure and the immediate priority is compatibility, **then** retaining the mean is a defensible reference condition because it is already the accepted interface and simple/parameter-free. This is not a claim that it preserves all relevant spatial semantics.
- **If** only code clarity/provenance is at issue, **then** refactor the seam while preserving exact values and state. A changed readout is not a semantics-preserving refactor.
- **If** an author-approved study identifies a specific ROI-local distinction that should affect the point but is suppressed by mean pooling, **then** a spatially aware alternative becomes a testable candidate. The study must distinguish mathematical capacity from observed semantic loss and improvement; greater capacity alone is not a justification.

**Future falsifiers (not executed):**

1. An algebraic witness can falsify injectivity of mean pooling by constructing two different `[256,7,7]` tensors with equal per-channel sums and fixed identical coordinates. This proof is expected to succeed; it does not diagnose the dataset.
2. A parity comparison can falsify a claimed refactor if any ROI vector, coordinate, occurrence order, validity bit, empty-set shape, gradient path or stage-state policy changes beyond an author-set tolerance.
3. Only a separately authorized, controlled visual/learning evaluation can distinguish whether additional spatial detail improves a thesis-relevant target. It must hold ROI boxes, visual input, split, point head and comparison policy fixed where possible; preserve no-leakage and identities; predeclare analysis and not treat test performance as architecture-selection feedback.

## 5. Boundary 3 — independent global visual representation

### 5.1 Current design and evidence

**[SOURCE]** The global extractor obtains a single ROI spanning each original image, transforms it through the same recorded letterbox geometry, and applies a separate `MultiScaleRoIAlign` call on the shared FPN maps. It samples to `[B,256,7,7]`. For a non-square input, the selected ROI is the transformed original extent and excludes letterbox padding, unlike the square canvas. It is generated even when a sample has zero component ROIs. The global point head currently consumes this spatial grid (1×1 channel projection to 32, flatten to 1568, then dense projection); it is not a global average of component vectors.

**[SOURCE + CP2/P4]** The component provider affects the component ROI call, not the explicit full-image ROI argument. CP2 P4 observed bit-identical global feature tensors across its fixed A, A-repeat, B and empty synthetic component providers, while component pooled values differed for the selected A/B boxes. This supports the intended separation in that fixture. It does not establish semantic independence from the components in the image, independence from shared FPN state, or real-image feature performance.

**[MATH]** The global representation can encode coarse spatial layout across 49 sampled locations and shares the upstream visual maps with component ROIs. Its pathway is independent of *which component boxes the provider returns*, but it is not produced by a separate backbone and is not statistically independent of component content. ROIAlign’s 7×7 sampling and preceding FPN are information bottlenecks relative to the full pixel image; whether those are consequential for pizza-level semantics is unknown.

### 5.2 Option A — retain full-original-image ROI and spatial grid

- **Contracts:** Preserve transformed original-image extent, separate global ROIAlign invocation, 256 channels, 7×7 grid, and one global representation per image regardless of component count. Keep it independent from the provider’s component boxes after the shared FPN pass.
- **Expressiveness / bias:** Retains a coarse 2-D arrangement for the global point projection. Unlike component readout, feature extraction does not spatially average the 7×7 map. The current global point head applies shared 1×1 channel weights and then location-specific dense weights on flattened positions, so some arrangement-dependent mapping is representable. The learned projection may still collapse distinctions; no target-semantic claim follows.
- **Optimization / stage:** Gradients flow from an active global-point path through the global ROI features into the FPN/backbone when those modules are trainable; in a frozen policy the visual state is fixed. CP2 P6 did not test feature quality and P7 did not test detector stages. The global branch should remain available for empty-component images; changing this could alter existing global/compositional/hybrid behavior and is outside B1.
- **Estimated cost:** One `[256,7,7]` output is 12,544 fp32 values, about 49 KiB per image, in addition to FPN activations. ROIAlign has one global ROI per sample, so this cost is constant in component count `K`; component ROI cost remains O(K). The current global point head’s first dense layer has `1568×256` weights after the 32-channel 1×1 reduction. These are shape-derived estimates, not measured runtime or total training memory.
- **Identity / inspection:** Existing feature cache stores the global 256×7×7 array and identifies original-extent/letterbox behavior, visual state and producer metadata. Keep original image extent, geometry, feature axes, ROI source/provenance and shared-backbone identity explicit. Existing read-only snapshot/dashboard behavior cannot recompute or reinterpret old arrays.
- **BOX/TOWN:** Preserve one `[d]` global pizza point through the current downstream interface, independent of the number of component rows. The visual pathway does not choose class binding, set membership, point-domain behavior or fusion. If the global feature changes, run/checkpoint/experiment provenance must change even if the resulting point is the same shape.
- **Evidence / risk:** Source plus CP2/P4 support component-provider independence in the stated setup. Neither establishes that global features encode recipe semantics, outperform composition, or remain invariant to changes in images, shared weights, preprocessing or feature cache. Retaining is a compatibility baseline, not a proven optimal readout.

### 5.3 Option B — refactor global extraction while preserving the interface/function

- **Scope:** Clarify the separate full-image ROI builder/readout boundary, share implementation utilities with the component ROI path only where that preserves the full original-extent behavior, and make the independent global branch explicit in the feature contract. Do not tie it to component-provider output or component counts.
- **Parity conditions:** Preserve exact original-extent vs canvas semantics, map set/ROI scale selection, output `[B,256,7,7]`, global availability for empty component sets, provider independence, gradients/state, and values within an author-approved tolerance. A helper shared by the two paths must not accidentally route global features through component ROI results.
- **Expressiveness / cost:** A truly identical refactor adds no representation or compute changes. There is no evidence that current duplication is a defect; two modules may be explicit safeguards for differing ROI roles.
- **Identity/dashboard / BOX-TOWN:** Keep the extraction-contract version and feature cache identity coherent; document whether old caches remain equivalent. Future dashboard inspection needs both component and global source extents separately. Point dimension, point domain, and fusion remain untouched.
- **Assessment:** Conditional on a specific maintenance or provenance goal and verified behavior parity. No evidence here requires merging the two ROI paths.

### 5.4 Option C — alternative global aggregation or readout

Possible families for author discussion, not selected:

- **Global average or max pooling** to one value/channel: smaller representation, but collapses explicit spatial layout (average pooling is itself non-injective; max pooling discards non-max locations).
- **Flattened grid projection**: expose all 12,544 visual values to a learned readout. This preserves cell identity up to the learned projection but increases dense input parameters and may overfit.
- **Spatial-pyramid bins**: preserve multiple coarse spatial regions rather than one grid or one global summary; changes width or requires a learned compression.
- **Learned attention/readout over grid locations**: weights positions according to image features; can adapt where to read, but adds parameters and is not guaranteed to retain all spatial information. Attention pooling literature on MIL is an analogy for a permutation-invariant learned readout, not direct evidence for a 2-D global image task.
- **Alternative multi-level global readout** from several FPN levels: could expose scale-specific information rather than the current per-ROI scale assignment; would increase feature/compute dependencies and alter the producer contract.

- **Contracts / approval:** Any changed global feature tensor shape or semantics requires explicit author approval under the B1 authorization. If preserving `[B,256,7,7]` as the feature output but changing the consumer’s aggregation, that is still a new global architecture and checkpoint meaning; shape equality does not make it a refactor. Keep one global point per image and preserve the empty-component case. Do not change point domain, composition or hybrid fusion in B1.
- **Expressiveness / bias:** Average pooling imposes translation/arrangement invariance over the grid; flattening preserves absolute bin index at input; pyramids trade detail for coarse spatial summaries; learned attention can select locations but may collapse or overfocus. Combining FPN levels could expose scale diversity but may duplicate correlated features. These are mathematical/architectural implications, not evidence of improved global semantics.
- **Optimization / stage:** Fixed pooling adds no parameters; learned attention/projection or multi-level fusion adds parameters and changes gradient allocation. If learned readout is part of the detector visual state, F9 stage freezing applies; if considered point projection, the stage ownership must be decided explicitly. Stage-3 shared feature maps can receive approved gradients, while selected coordinates and discrete choices remain detached. The readout itself must not be used to smuggle gradients through boxes or change the existing point/hybrid contracts.
- **Estimated cost:** Average/max pooling costs O(256×49) per image and reduces stored output to 256 values. A direct flattened 12,544-to-256 projection has about 3.21M weights/MACs in that layer; relative to the current 1568-to-256 dense layer, its input layer is 8× larger, before considering the current 1×1 convolution. Pyramid/attention costs depend on bin count, projection width and number of heads/levels. No end-to-end timing is available.
- **Cache/checkpoint / inspection:** A changed global producer/readout must be versioned with its grid/levels, pooling family, weights, initialization, ROI extent and dimensionality. Current cache stores raw 256×7×7 global features, so a downstream readout experiment might reuse those only if backbone/ROI producer identity and data are identical; a changed backbone or ROIAlign path requires recomputation. Do not treat the old cache as evidence for predictions from a new point head. An approved future inspector should report image extent, grid axes, pooling/readout, feature provenance and empty-component behavior; current dashboard remains read-only/metadata-only.
- **BOX/TOWN / risks:** Existing `[d]` and `[N,d]` integration shapes remain only if the same downstream head output is preserved. Any distribution shift in points changes the geometry queries and requires a new experiment identity. Main risks are loss of layout, added estimation variance/capacity, optimization difficulty, confounding global vs component changes, and misrepresenting CP2’s synthetic equality as semantic independence.

### 5.5 Conditional assessment and discriminating evidence

- **If** an independent whole-image point and empty-component support are required while preserving current interfaces, **then** retaining the full-image ROI/grid is the directly source-supported baseline. CP2/P4 adds a bounded synthetic check that component-provider variants did not alter that tensor.
- **If** the goal is only a clearer source seam and traceable ROI extent, **then** an interface-preserving refactor is possible, provided it does not couple the global call to the component provider or change the values.
- **Only if** an author-approved evaluation identifies a global-context/layout limitation or a separately declared compute constraint should a new pooling/readout be considered. The experiment must distinguish representational capacity from training success and must not redesign hybrid fusion or point-domain semantics in this checkpoint.

**Future falsifiers (not executed):**

1. Provider independence is falsified by a deterministic fixed-image/fixed-weight comparison where changing only component-provider boxes changes the global tensor. Source inspection and CP2/P4 currently support independence under those fixed conditions; CP2 is synthetic and does not establish broad runtime coverage.
2. Empty-component support is falsified if the global representation is absent or changes shape when the component count becomes zero. Current source and the existing CP2 P4 fixture report this path present; no test was rerun here.
3. A semantic/global-readout claim requires an author-approved real-image comparison under a predeclared evaluation protocol with unchanged component path and point/fusion semantics. Feature-tensor difference alone is not proof of semantic improvement.
